# المساهمة بترجمة XPENC

يستخدم المشروع نظام Flutter الرسمي للترجمة `gen-l10n` وملفات `ARB`.
كل لغة لها ملف مستقل، مثل:

- `lib/l10n/app_en.arb` — الإنجليزية (المرجع الأساسي)
- `lib/l10n/app_ar.arb` — العربية
- `lib/l10n/app_fr.arb` — الفرنسية عند إضافتها

## إضافة لغة جديدة

1. ثبّت Python 3 وFlutter وفق تعليمات بناء المشروع.
2. أنشئ ملف اللغة بالأمر `python3 scripts/new_locale.py fr`، مع استبدال `fr` برمز لغتك.
3. افتح الملف الجديد وترجم **القيم النصية** حسب المقصود في واجهة مالية، وليس كلمةً بكلمة.
4. لا تغيّر أسماء المفاتيح، أو المتغيرات المحاطة بأقواس مثل `{amount}` و`{date}` و`{count}`.
5. حافظ على تراكيب جمع ICU حيث توجد، مع مراعاة قواعد اللغة المستهدفة.
6. نفّذ:
   - `python3 scripts/check_l10n.py`
   - `flutter pub get --enforce-lockfile`
   - `flutter gen-l10n`
   - `flutter analyze`
   - `flutter test`
7. افحص التطبيق فعليًا على هاتف أو محاكي، بما فيه الرسائل والتنبيهات وأدوات الشاشة الرئيسية.

**لا تحتاج إلى تعديل ملفات Dart لمجرد تسجيل لغة جديدة.** تظهر اللغات الجديدة تلقائيًا في قائمة اختيار لغة التطبيق بعد توليد ملفات الترجمة.

## تعليمات الجودة

- يجب أن تكون المصطلحات المالية طبيعية ودقيقة.
- لا تترجم نصوص المستخدم أو أسماء التجار المخزنة أو معرفات البيانات.
- راجع الأرقام ورموز العملات وتواريخ الاستحقاق.
- اختبر اتجاه الواجهة من اليمين لليسار مع العربية والعبرية والفارسية عند إضافة أي منها.
- راجع الرسائل المنبثقة والأخطاء ووسوم قارئ الشاشة والتنبيهات، وليس عناوين الأزرار فقط.
- انتبه إلى أن القواميس المكتملة لا تعني أن كل نص في الكود يستخدم نظام الترجمة؛ يساعد `scripts/audit_unlocalized.py` في اكتشاف النصوص المتبقية، لكنه ليس فحصًا شاملًا.
- لملفات Android الأصلية، أنشئ `android/app/src/main/res/values-<code>/strings.xml` بالمفاتيح نفسها.
- **لا يُقدَّم طلب دمج حتى تنجح اختبارات Flutter، ويُراجَع تعريب جميع الشاشات بصريًا.**
